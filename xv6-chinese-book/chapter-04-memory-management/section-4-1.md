# 第 4 章：内存管理深入

在前面的章节中，我们已经多次接触到内存管理的概念，例如进程地址空间、页表、以及用户堆的分配。本章将更系统地深入探讨 xv6 中的内存管理机制，首先从内核对物理内存的管理开始，特别是物理页的分配与释放。

## 4.1 内核物理内存管理：页分配 (Kernel Physical Memory Management: Page Allocation)

操作系统内核自身也需要使用内存。这些内存用于存储内核代码、内核数据结构（如进程表、文件表、inode 表等）、内核栈（每个进程都有一个）、以及在为用户进程分配内存时所需的临时数据结构（如页表）。因此，内核必须拥有一套高效且可靠的机制来管理可用的物理内存。

### 1. 内核内存管理简介

内核内存管理的主要职责包括：

*   **跟踪可用内存**：内核需要知道哪些物理内存区域是空闲的，哪些已经被占用。
*   **提供分配机制**：当内核的其他部分（或代表用户进程的部分）需要内存时，内存管理器必须能够分配一块合适的内存。
*   **提供回收机制**：当分配出去的内存不再被使用时，必须能够将其回收并标记为空闲，以供后续分配。
*   **保证隔离与保护**：虽然本节主要关注内核自身的物理内存分配，但最终这些物理内存会被用于构建用户进程的地址空间或内核数据结构，页表机制会在此基础上提供隔离和保护。

在 xv6 中，内核对物理内存的管理是以“页”（Page）为基本单位的。

### 2. 物理页：分配的基本单位

物理内存被划分为固定大小的块，称为**物理页 (Physical Pages)** 或**页帧 (Page Frames)**。在 xv6 (以及许多现代 x86 系统) 中，一个物理页的大小通常是 **4KB (4096 字节)**。

以页为单位进行管理有几个好处：
*   **简化管理**：内核只需要跟踪页的状态（空闲或已分配），而不需要处理任意大小的内存块。
*   **与 MMU 配合**：分页硬件（MMU）也是以页为单位进行地址转换和权限控制的。因此，以页为单位分配物理内存可以很自然地与 MMU 的页表机制相结合。
*   **减少外部碎片**：虽然不是完全消除，但固定大小的分配单元有助于管理和减少外部碎片（即由于大量小的、不连续的空闲块导致无法满足较大内存请求的情况）。

当内核需要为某些数据结构（如一个新的页表、一个用户进程的新代码页或数据页）分配内存时，它会从一个空闲物理页池中取出一个或多个页。

### 3. 空闲页链表 (`kmem` 结构与 `kalloc.c`)

xv6 使用一种非常简单直接的方式来跟踪所有可用的物理页：一个**空闲页链表 (Free Page List)**。

相关的代码和数据结构主要在 `kernel/kalloc.c` 文件中。

#### a. `kmem` 结构与 `freelist`

```c
// kernel/kalloc.c
struct {
  struct spinlock lock; // 用于保护空闲链表的自旋锁
  int use_lock;         // 是否使用锁 (多核启动后才使用)
  struct run *freelist; // 指向空闲物理页链表的头部
} kmem;

struct run {
  struct run *next; // 指向下一个空闲页 (run 结构本身存储在空闲页的起始位置)
};
```

*   **`kmem` 结构体**：这是一个全局静态结构体，包含了管理空闲物理内存所需的所有信息。
    *   **`lock`**: 一个自旋锁 (`struct spinlock`)。在多处理器系统中，多个 CPU 可能同时尝试分配或释放物理页。这个锁用于保护对 `freelist` 的访问，确保操作的原子性，防止竞争条件。
    *   **`use_lock`**: 一个标志位。在系统启动的早期阶段（单核环境），锁是不必要的，此时 `use_lock` 为 0。当多核处理器初始化完成后，`use_lock` 会被设置为 1，此后所有对 `freelist` 的操作都必须先获取该锁。
    *   **`freelist`**: 一个指向 `struct run` 类型的指针。这是空闲页链表的头指针。如果 `freelist` 为 `NULL`，则表示当前没有可用的空闲物理页。

*   **`struct run` 结构体**：
    *   这个结构体非常简单，只有一个成员 `next`，它指向链表中的下一个 `struct run`。
    *   巧妙之处在于，`struct run` 结构本身就存储在它所代表的那个空闲物理页的起始位置。因为一个物理页是 4KB，而 `struct run` (一个指针) 只占 4 或 8 字节，所以有足够的空间。当一个物理页被释放并加入到 `freelist` 时，它的前几个字节被用作 `struct run` 结构来链接到链表中。当这个页被分配出去后，它的全部 4KB 空间都可以被使用者自由使用。

#### b. 初始化空闲链表 (`kinit1` 和 `kinit2`)

在 xv6 启动过程中，物理内存需要被初始化并加入到 `kmem.freelist` 中。这个过程分两阶段完成，主要在 `kernel/main.c` 中调用，实际释放在 `kernel/kalloc.c` 的 `freerange` 函数。

1.  **`kinit1(void *vstart, void *vend)`**:
    *   在系统引导的早期（多处理器尚未完全启动，分页也可能尚未完全开启或只开启了简单映射），会调用 `kinit1`。
    *   它负责初始化第一部分可用物理内存。这个范围通常是从内核代码和数据段结束的地方（由链接器脚本定义的 `end` 符号标记）到一个初始的较小的物理内存上限（例如，前 4MB 或 `PHYSTOP` 定义的初始物理内存顶）。
    *   `kinit1` 会将 `kmem.use_lock` 设置为 0（因为此时还是单核引导环境）。
    *   然后调用 `freerange(vstart, vend)`，将 `vstart` 到 `vend` 之间的物理内存逐页加入到 `freelist`。

2.  **`kinit2(void *vstart, void *vend)`**:
    *   在多处理器初始化完成，并且内核的高地址映射（`KERNBASE` 以上）也设置完毕后，会调用 `kinit2`。
    *   它负责初始化剩余的可用物理内存，通常是从 `kinit1` 处理的内存末尾到系统可用的物理内存顶端 (`PHYSTOP`)。
    *   `kinit2` 会将 `kmem.use_lock` 设置为 1，因为此时系统可能已经在多核模式下运行。
    *   然后同样调用 `freerange(vstart, vend)`。

**`freerange(void *vstart, void *vend)` 函数**:
*   这个函数（位于 `kernel/kalloc.c`）接收一个物理地址范围（已由内核虚拟地址直接映射）。
*   它首先将 `vstart` 对齐到下一个页边界（`PGROUNDUP`）。
*   然后，它循环地将从对齐后的 `vstart` 开始到 `vend` 结束的每一页物理内存调用 `kfree()`。`kfree()` 会将这些页逐个加入到 `kmem.freelist` 中。

### 4. `kalloc()` - 分配一个物理页

当内核需要一个新的物理页时（例如，为用户进程的 `sbrk` 分配内存，或者为新的页表分配内存），它会调用 `kalloc()` 函数（定义在 `kernel/kalloc.c`）。

```c
// kernel/kalloc.c
// Allocate one 4096-byte page of physical memory.
// Returns a pointer that the kernel can use.
// Returns 0 if the memory cannot be allocated.
void*
kalloc(void)
{
  struct run *r;

  if(kmem.use_lock) // 如果 use_lock 为真，则获取锁
    acquire(&kmem.lock);

  r = kmem.freelist; // 从链表头获取一个空闲页
  if(r) // 如果链表不为空
    kmem.freelist = r->next; // 更新链表头指向下一个空闲页

  if(kmem.use_lock) // 释放锁
    release(&kmem.lock);

  // 如果成功分配到页 (r 不为 NULL)，则将该页内容填充为 1
  // 这有助于捕捉那些错误地使用了未初始化内存的bug
  // 因为对这个内存的读写很可能会因为非零值而表现出异常
  if(r)
    memset((char*)r, 1, PGSIZE); // PGSIZE 是页大小 (4096)
  return (void*)r; // 返回指向该物理页的内核虚拟地址指针
}
```

`kalloc()` 的步骤如下：

1.  **获取锁**：如果 `kmem.use_lock` 为真，调用 `acquire(&kmem.lock)` 获取自旋锁，以保护对 `freelist` 的并发访问。
2.  **从链表头移除页**：
    *   将 `kmem.freelist`（链表头指针）的值赋给局部变量 `r`。
    *   如果 `r` 不为 `NULL`（即链表中有空闲页），则将 `kmem.freelist` 更新为 `r->next`，即指向原链表中的第二个页。这相当于从链表中“弹出”了第一个页。
3.  **释放锁**：如果之前获取了锁，现在调用 `release(&kmem.lock)` 释放它。
4.  **清零（或填充）内存 (可选但推荐)**：
    *   如果成功分配到了一个页（`r` 不为 `NULL`），xv6 的实现是调用 `memset((char*)r, 1, PGSIZE)` 将整个页的 4096 字节都设置为 1。
    *   这是一种调试技巧。将内存设置为一个非零的、可识别的模式，有助于后续如果代码错误地使用了未初始化的内存（例如，把它当作指针或索引），更容易暴露出问题。在许多系统中，出于安全考虑，新分配给用户空间的页通常会被清零，以防止信息泄露（即一个进程读到之前另一个进程留下的数据）。xv6 内核分配页给内核自身使用时，用 1 填充主要是为了调试内核代码。当这些页最终被用于用户空间时（例如通过 `allocuvm`），通常会在映射到用户空间之前或之后根据需要进行清零。
5.  **返回指针**：返回 `r`（它是一个指向物理页起始位置的内核虚拟地址）。如果 `kmem.freelist` 开始时就为空，`r` 会是 `NULL`，`kalloc()` 就会返回 `NULL`，表示分配失败。

### 5. `kfree()` - 释放一个物理页

当内核确定一个之前由 `kalloc()` 分配出去的物理页不再被使用时，它会调用 `kfree()` 函数（定义在 `kernel/kalloc.c`）将其归还到空闲页链表中。

```c
// kernel/kalloc.c
// Free the page of physical memory pointed at by v,
// which normally should have been returned by a call to kalloc().
// (The exception is when initializing the allocator; see kinit above.)
void
kfree(void *v)
{
  struct run *r;

  // 基本的错误检查
  if((uint)v % PGSIZE || (char*)v < end || V2P(v) >= PHYSTOP)
    panic("kfree"); // 如果地址未按页对齐，或地址在内核代码/数据区，或超出物理内存上限，则panic

  // 将页内容填充为 1 (可选，用于调试，帮助发现 use-after-free 等问题)
  memset(v, 1, PGSIZE);

  if(kmem.use_lock) // 获取锁
    acquire(&kmem.lock);

  r = (struct run*)v; // 将要释放的页的地址转换为 struct run*
  r->next = kmem.freelist; // 将它的 next 指针指向当前的链表头
  kmem.freelist = r;      // 更新链表头为这个刚释放的页

  if(kmem.use_lock) // 释放锁
    release(&kmem.lock);
}
```

`kfree()` 的步骤如下：

1.  **基本错误检查**：
    *   `if((uint)v % PGSIZE ...)`：检查传入的地址 `v` 是否是页对齐的（即是否是 `PGSIZE` 的整数倍）。物理页只能整页释放。
    *   `(char*)v < end`: 检查地址 `v` 是否小于 `end`（内核代码和静态数据区的末尾）。内核不应该释放其自身的代码或核心数据结构所占用的静态分配的内存。
    *   `V2P(v) >= PHYSTOP`: 检查地址 `v`（转换为物理地址后）是否超出了已知的物理内存上限 `PHYSTOP`。
    *   如果任何检查失败，调用 `panic("kfree")` 使内核崩溃。这表明内核中存在严重的内存管理错误。

2.  **填充内存 (可选)**：
    *   `memset(v, 1, PGSIZE)`：与 `kalloc()` 类似，将要释放的页内容填充为 1。这有助于调试，例如，如果代码在释放后仍然尝试使用该内存（use-after-free bug），填充的 1 可能会导致其行为异常，从而更容易被发现。

3.  **获取锁**：如果 `kmem.use_lock` 为真，获取 `kmem.lock` 自旋锁。

4.  **将页添加到链表头**：
    *   将指针 `v` 强制类型转换为 `struct run *r`。这意味着从现在开始，内核将这块 4KB 内存的起始部分视为一个 `struct run` 结构。
    *   `r->next = kmem.freelist;`：将 `r` 的 `next` 指针指向当前 `kmem.freelist` 的头部（即之前链表中的第一个空闲页）。
    *   `kmem.freelist = r;`：更新 `kmem.freelist` 的头部，使其指向 `r`。这样，刚被释放的页就成为了空闲链表中的第一个元素。

5.  **释放锁**：如果之前获取了锁，现在释放它。

### 6. xv6 页分配器的局限性与简洁性

xv6 的物理页分配器（`kalloc`/`kfree` 和 `kmem` 结构）为了教学目的而设计得非常简洁：

*   **单一空闲链表**：它只使用一个简单的后进先出（LIFO，通过在头部添加和移除）的空闲链表。
*   **无复杂算法**：它没有实现更高级的物理内存管理算法，例如：
    *   **伙伴系统 (Buddy System)**：这种算法尝试减少外部碎片，通过维护不同大小（2的幂次方）的空闲块链表，并在分配和释放时进行合并和分裂。
    *   **坯层分配器 (Slab Allocator)**：这种算法通常构建在页分配器之上，用于高效地管理内核中常用的小对象的分配和释放（例如，`struct proc`，`struct file` 等），它通过缓存这些对象来避免反复初始化和销毁的开销。
*   **无内存区域或 NUMA 支持**：它假设所有物理内存都是同质的，并且没有针对不同内存区域（例如，DMA区域）或非一致内存访问（NUMA）架构进行优化。
*   **碎片问题**：虽然以页为单位分配可以管理外部碎片，但如果内核自身频繁申请和释放不同生命周期的小块内存（而 `kalloc` 只能分配整页），可能会导致一定程度的内部碎片（页内未使用的空间）。不过，xv6 内核相对简单，其内核动态内存需求不大，所以这不是一个严重问题。

这种简洁性使得 xv6 的物理内存分配代码易于理解，清晰地展示了核心机制。

### 7. 与用户进程内存的关系

内核物理页分配器 (`kalloc`) 是用户进程获得内存的基础。当用户进程需要更多内存时（例如，通过 `fork` 复制地址空间，通过 `sbrk` 扩展堆，或通过 `exec` 加载新程序），内核中的相关模块会执行以下操作：

1.  **`allocuvm()` (分配用户虚拟内存)**:
    *   这个函数（在 `kernel/vm.c` 中）负责为用户进程的页目录 `pgdir` 分配指定范围的虚拟地址。
    *   对于这个虚拟地址范围内的每一页，`allocuvm` 会：
        1.  调用 `kalloc()` 来获取一个空闲的物理页。
        2.  如果 `kalloc()` 成功，`allocuvm` 会调用 `mappages()` 函数，在用户进程的页表中建立一个 PTE，将用户虚拟地址映射到这个刚分配到的物理页，并设置适当的权限位（如 `PTE_W` 可写, `PTE_U` 用户可访问）。
        3.  如果 `kalloc()` 失败（返回 `NULL`），`allocuvm` 会停止分配，并可能需要回滚已做的分配（通过 `deallocuvm`），然后向上层调用者报告失败。

2.  **`deallocuvm()` (释放用户虚拟内存)**:
    *   当用户进程的内存被回收时（例如，`sbrk` 传入负值，或进程 `exit`），`deallocuvm` 会被调用。
    *   它会遍历指定虚拟地址范围内的页表项 (PTE)。
    *   对于每个有效的、已映射的 PTE：
        1.  获取该 PTE 指向的物理页地址。
        2.  调用 `kfree()` 将该物理页归还到内核的空闲链表。
        3.  清除该 PTE（标记为无效）。

因此，`kalloc()` 和 `kfree()` 是 xv6 内存管理体系的基石。它们管理着系统中所有可供动态分配的物理页资源，无论是为内核自身的数据结构服务，还是为用户进程的地址空间提供实际的物理存储。理解了 `kalloc.c` 的工作原理，就掌握了 xv6 物理内存的脉搏。
