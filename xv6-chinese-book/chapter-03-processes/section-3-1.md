# 第 3 章：进程深入

在第 2 章中，我们对进程及其生命周期有了初步的了解。本章将更深入地探讨与进程相关的几个核心主题，首先从进程的内存视角——地址空间开始。

## 3.1 进程地址空间 (Process Address Space)

每个在系统中运行的进程都需要使用内存来存储其指令、数据、以及运行时产生的临时信息。操作系统的一个核心任务就是有效地管理这些内存，并为每个进程提供一个清晰、受保护的内存视图。这个视图就是所谓的“地址空间”。

### 1. 什么是地址空间？

**地址空间 (Address Space)** 是指一个进程可以合法访问的内存地址的范围。对于一个进程而言，它“看到”的内存并不是计算机上全部的物理内存，而是一个独立的、私有的地址范围。这意味着每个进程都认为自己拥有一整块从某个起始地址（通常是 0）开始的连续内存区域，而无需关心其他进程的内存使用情况，也不必关心这些地址是如何对应到计算机实际的物理内存芯片上的。

**关键特性：**

*   **独立性与私有性**：每个进程都有其自己独立的地址空间。一个进程不能直接访问另一个进程的地址空间（除非通过共享内存等特殊机制，xv6 中不涉及）。这种隔离性是操作系统提供保护和安全的基础。如果一个进程意外地（或恶意地）尝试写入一个无效地址，它只会破坏自己的数据，而不会影响其他进程或操作系统内核。
*   **一致性视图**：尽管物理内存可能是碎片化的，或者程序的不同部分可能加载到物理内存的不同位置，但进程看到的其地址空间通常是连续且组织良好的。

### 2. 虚拟地址 vs. 物理地址 (Virtual vs. Physical Addresses)

理解地址空间的关键在于区分虚拟地址和物理地址：

*   **虚拟地址 (Virtual Address)**：是进程在其地址空间中使用的地址。当程序被编译和链接时，它使用的是虚拟地址。例如，一条指令可能要从地址 `0x1000` 读取数据，或者一个指针可能指向地址 `0x20000`。这些都是虚拟地址。
*   **物理地址 (Physical Address)**：是计算机内存硬件（RAM芯片）实际使用的地址。CPU 在访问内存控制器时，最终需要的是物理地址。

**地址转换 (Address Translation)：**

操作系统内核和硬件（主要是内存管理单元 - Memory Management Unit, MMU）协同工作，将进程使用的虚拟地址实时地转换成物理地址。这个转换过程对进程本身是透明的。
*   **内核的角色**：内核为每个进程维护一套映射规则（通常以页表的形式存储）。当创建一个进程或进程请求更多内存时，内核会分配物理内存，并更新该进程的页表来记录虚拟地址到物理地址的映射关系。
*   **MMU 的角色**：MMU 是 CPU 内部的一个硬件组件。当 CPU 执行一条访问内存的指令时，它会把指令中的虚拟地址发送给 MMU。MMU 使用内核设置好的页表信息，查找对应的物理地址，然后将物理地址发送给内存控制器，从而完成数据的读取或写入。如果 MMU 发现一个虚拟地址没有有效的物理地址映射（例如，进程试图访问一个未分配的地址），它会产生一个硬件异常（在 x86 中称为“页错误”或 Page Fault），将控制权交给内核来处理。

这种虚拟地址到物理地址的转换机制带来了巨大的灵活性和强大的功能，如内存保护、按需分页（xv6 中未完全实现）、将不同进程的虚拟地址映射到相同的物理内存以实现共享等。

### 3. xv6 中进程地址空间的布局 (Layout of a Process Address Space in xv6)

xv6 为每个用户进程定义了一个典型的地址空间布局，从低地址到高地址大致如下：

```
+------------------+  <- 0 (KERNBASE - 1, or 2GB for xv6 on x86) / (MAXVA for RISC-V)
|      Stack       |  (用户栈，向下增长)
|        |         |
|        v         |
|                  |
|   (Guard Page)   |  (栈与堆之间的保护页，防止相互越界)
|                  |
|        ^         |
|        |         |
|       Heap       |  (用户堆，向上增长，通过 sbrk/malloc 分配)
+------------------+
|        BSS       |  (未初始化全局/静态变量，零初始化)
+------------------+
|       Data       |  (已初始化全局/静态变量)
+------------------+
|       Text       |  (程序代码，只读)
+------------------+  <- 0 (虚拟地址空间的底部)
```

让我们逐一解释这些段：

*   **Text (代码段)**：
    *   位于地址空间的最低部分。
    *   存储程序的机器指令。
    *   通常是只读的，以防止进程意外或恶意地修改其自身的代码。xv6 在加载程序时，会将这部分内存区域的页表项设置为不允许写入。
    *   这部分内容来自可执行文件的代码部分。

*   **Data (数据段)**：
    *   紧随代码段之后。
    *   存储程序中已初始化的全局变量和静态变量。例如，`int count = 10;` 或 `static char *name = "xv6";`。
    *   这部分内容也来自可执行文件的数据部分，在程序加载时被复制到内存中。
    *   这部分内存是可读可写的。

*   **BSS (BSS段)**：
    *   紧随数据段之后。BSS 是 "Block Started by Symbol" 的缩写。
    *   存储程序中未初始化的全局变量和静态变量。例如，`static char buffer[1024];` 或 `int temp_results[100];`（如果它们是全局或静态的）。
    *   按照 C 语言标准，这些变量在程序启动时必须被初始化为零。xv6 在加载程序时，会分配这部分内存，并将其清零，而可执行文件本身通常不存储这些零值（只记录 BSS 段的大小），以节省磁盘空间。
    *   这部分内存也是可读可写的。

*   **Heap (堆)**：
    *   位于 BSS 段之上。
    *   用于动态内存分配。当程序在运行时需要一块内存时（例如，通过 C 库函数 `malloc()`），就可以从堆中分配。
    *   在 xv6 中，堆的增长是通过 `sbrk()` 系统调用来实现的。`sbrk(n)` 会将进程的内存上限（堆的顶部）增加 `n` 字节，并返回新分配区域的起始地址（如果 `n` 为负数，则表示收缩堆）。
    *   堆是向上增长的（即向着更高的地址方向扩展）。
    *   这部分内存是可读可写的。

*   **Stack (栈)**：
    *   位于用户地址空间的最高部分。
    *   用于存储函数调用的信息（返回地址、参数、保存的寄存器）以及函数内部的局部变量。
    *   每当一个函数被调用，一个新的栈帧（stack frame）会被压入栈顶；当函数返回时，其栈帧会从栈顶弹出。
    *   栈是向下增长的（即向着更低的地址方向扩展）。
    *   在 xv6 中，当 `exec()` 系统调用设置新程序的地址空间时，会为用户栈分配一页初始内存。如果程序需要更多的栈空间（例如，由于深度函数调用或大的局部数组），MMU 在访问超出当前已分配栈区域但仍属于合法栈扩展区（低于当前栈顶但高于堆）的地址时会产生页错误。xv6 的页错误处理程序会检查这种情况，并按需分配新的物理页给栈。
    *   这部分内存是可读可写的。

*   **Guard Page (保护页)**：
    *   在 xv6 的典型实现中，通常会在堆的顶部和栈的底部之间留有一个未映射的虚拟地址区域（或标记为不可访问的页），作为“保护页”。
    *   它的作用是防止堆向上增长与栈向下增长时发生碰撞。如果堆或栈溢出并试图访问这个保护区域，会触发页错误，内核可以捕获这个错误并终止进程，而不是让它们悄无声息地相互破坏数据。xv6 中这个保护页的实现可能比较隐式，主要体现在堆的上限（由 `proc->sz` 记录）和栈的分配逻辑上。当栈增长时，如果它试图分配到已经被堆使用的区域，分配会失败。

### 4. 内核空间 vs. 用户空间 (Kernel Space vs. User Space)

xv6（以及大多数现代操作系统）的地址空间设计中有一个重要的概念：每个进程的地址空间不仅包含它自己的用户代码和数据（用户空间），还包含了操作系统内核的映射（内核空间）。

*   **用户空间 (User Space)**：这是进程地址空间中较低的部分（在 xv6/x86 中，通常是从虚拟地址 0 到 `KERNBASE`，`KERNBASE` 通常是 2GB）。这部分包含了我们上面讨论的 Text, Data, BSS, Heap, 和 Stack。用户程序只能直接访问用户空间的地址。
*   **内核空间 (Kernel Space)**：这是进程地址空间中较高的部分（在 xv6/x86 中，从 `KERNBASE` 到地址空间的顶部）。这部分内存映射了操作系统的内核代码和数据。
    *   **共享映射**：重要的是，所有进程的内核空间部分都映射到相同的物理内存区域，即实际的内核。这意味着内核代码和核心数据结构（如进程表）在物理上只有一份。
    *   **保护**：尽管内核空间被映射到每个进程的地址空间中，但它受到 CPU 特权级别的保护。只有当 CPU 处于内核态（特权级别 0）时，才能访问内核空间的内存。当进程运行在用户态（特权级别 3）时，任何尝试直接访问内核空间地址的行为都会被 MMU 阻止，并产生一个硬件异常（通常是段错误或页错误）。
    *   **系统调用和中断**：当发生系统调用或硬件中断时，CPU 会从用户态切换到内核态，此时内核代码才能安全地访问内核空间。

这种设计的好处是，当内核需要代表当前进程执行操作时（例如，在系统调用期间），它可以直接访问当前进程的用户空间数据（通过检查和复制参数），也可以直接访问内核自身的数据结构，而无需进行复杂的地址空间切换。

### 5. xv6 中的页表 (Page Tables in xv6)

xv6 使用基于分页的虚拟内存管理。分页是将虚拟地址空间和物理内存都划分为固定大小的块（称为“页”，page）的机制。在 xv6 (x86) 中，页的大小通常是 4KB。

**页表的作用：**

页表是存储虚拟页到物理页（也称为页帧，page frame）映射关系的数据结构。CPU 的 MMU 使用页表来将虚拟地址转换为物理地址。

xv6 使用两级页表结构（这是 x86 架构在非 PAE 模式下的标准）：

1.  **页目录 (Page Directory)**：
    *   每个进程都有一个自己的页目录。`struct proc` 中的 `pgdir` 字段（类型为 `pde_t*`，即页目录项指针）指向该进程的页目录。
    *   页目录本身是一个物理页（4KB），包含 1024 个页目录项（Page Directory Entries, PDEs）。
    *   每个 PDE（类型为 `pde_t`）大小为 4 字节。它负责映射 4MB 的虚拟地址范围（因为一个 PDE 指向一个页表，而一个页表可以映射 1024 个 4KB 的页，即 1024 * 4KB = 4MB）。
    *   PDE 包含：
        *   一个指向页表（Page Table）的物理基地址（高 20 位）。
        *   一些标志位，如 `PTE_P` (Present - 是否存在)、`PTE_W` (Writable - 是否可写)、`PTE_U` (User - 是否允许用户态访问) 等。

2.  **页表 (Page Table)**：
    *   页表也是一个物理页（4KB），包含 1024 个页表项（Page Table Entries, PTEs）。
    *   每个 PTE（类型为 `pte_t`）大小为 4 字节。它负责映射一个 4KB 的虚拟页到对应的 4KB 物理页帧。
    *   PTE 包含：
        *   一个指向物理页帧的物理基地址（高 20 位）。
        *   一些标志位，与 PDE 中的类似，但应用于单个页的级别（如 `PTE_P`, `PTE_W`, `PTE_U`）。

**地址转换过程简述：**

当 MMU 需要翻译一个 32 位虚拟地址时：
1.  **页目录索引**：虚拟地址的高 10 位 (位 22-31) 用作索引，在当前进程的页目录中选择一个 PDE。
2.  **页表索引**：虚拟地址的中间 10 位 (位 12-21) 用作索引，在从选定 PDE 指向的页表中选择一个 PTE。
3.  **物理地址计算**：选定 PTE 的高 20 位给出了物理页帧的基地址。虚拟地址的低 12 位 (位 0-11) 作为页内偏移，与物理页帧基地址组合起来，形成最终的 32 位物理地址。
MMU 在此过程中还会检查 PDE 和 PTE 中的标志位，以确保访问是合法的（例如，页是否存在，是否有写入权限，是否有用户态访问权限等）。

**页表与进程操作：**

*   **`fork()` 与页表**：当 `fork()` 创建一个新进程时，它需要为子进程复制父进程的地址空间。这是通过 `copyuvm()` 函数（在 `kernel/vm.c` 中）完成的。`copyuvm()` 会为子进程创建一个新的页目录，然后遍历父进程的页表。对于父进程中每个映射到用户空间的有效 PTE，`copyuvm()` 会：
    1.  为子进程分配一个新的物理页帧。
    2.  将父进程对应物理页的内容复制到这个新的物理页帧中。
    3.  在子进程的相应页表中创建一个新的 PTE，使其指向这个新的物理页帧，并复制父进程 PTE 的标志位（如权限）。
    内核空间的映射通常是直接复制 PDE（因为所有进程共享内核空间），而不会复制物理页帧。

*   **`exec()` 与页表**：当 `exec()` 加载一个新程序时，它会构建一个全新的用户地址空间：
    1.  首先，它会创建一个新的、几乎为空的页目录（通常只包含内核空间的映射）。
    2.  然后，它会根据可执行文件中的段信息（如代码段、数据段），为这些段分配物理内存页，并将文件内容加载到这些页中。同时，它会在新页目录和相应的页表中创建 PTE 来映射这些用户页。
    3.  它还会为 BSS 段分配并清零物理页，并设置映射。
    4.  最后，它会为用户栈分配一个初始的物理页，并设置映射。
    旧进程的用户空间页表和物理页（如果之前有的话）会被释放。

理解进程地址空间的布局和页表机制是深入学习操作系统内存管理、进程切换以及系统调用实现等后续内容的基础。xv6 通过简洁的两级页表实现了每个进程独立的、受保护的虚拟地址空间。
