## 3.3 `exec()` 系统调用：加载新程序

`exec()` 是类 Unix 操作系统中一个核心的系统调用，它允许一个进程用一个新的程序映像替换其当前的程序映像。这意味着当前进程的代码、数据、堆和栈都会被新程序的内容所取代，但进程 ID (PID) 通常保持不变。本节将深入探讨 xv6 中 `exec()` 的实现。

### 1. `exec()` 的目的与用途

`exec()` (发音为 "execute"，执行) 的主要目的是运行一个新的程序。与 `fork()` 创建一个当前进程的副本不同，`exec()` 会彻底改变当前进程的执行内容。

**`fork()` 与 `exec()` 的组合：**

在实践中，`exec()` 经常与 `fork()` 结合使用，这是 Unix/Linux 系统中创建新任务的标准模式：

1.  **`fork()`**: 父进程首先调用 `fork()` 创建一个子进程。子进程是父进程的一个几乎完全相同的副本。
2.  **`exec()`**:
    *   **子进程**: 子进程接着调用 `exec()` 来加载并执行一个全新的程序。如果 `exec()` 成功，子进程的内存映像被新程序替换，子进程开始执行新程序的代码。
    *   **父进程**: 父进程通常会调用 `wait()` 等待子进程结束，或者继续执行自己的任务。

这种“先复制再替换”的模式非常灵活，它允许子进程在执行 `exec()` 之前进行一些设置（例如，重定向文件描述符、改变环境变量等），这些设置可以影响即将执行的新程序。xv6 中的 shell (`user/sh.c`) 就是通过这种方式来执行用户输入的命令的。

如果一个进程直接调用 `exec()` 而没有先 `fork()`，那么一旦 `exec()` 成功，该进程自身的代码就会被新程序替换，它将永远不会从 `exec()` 调用之后的代码继续执行。

### 2. xv6 中 `exec()` 的实现

xv6 中的 `exec()` 系统调用由用户程序发起，内核中的 `sys_exec()` 函数（位于 `kernel/sysproc.c`）处理该请求，但实际的核心逻辑在 `exec()` 函数（位于 `kernel/exec.c`）中实现。

```c
// kernel/sysproc.c
int
sys_exec(void)
{
  char *path, *argv[MAXARG]; // MAXARG 是最大参数个数
  int i;
  uint uargv, uarg;

  // 从用户空间获取可执行文件路径和参数列表
  if(argstr(0, &path) < 0 || argptr(1, (void*)&uargv, sizeof(char*)*MAXARG) < 0){
    return -1;
  }
  // 将参数字符串指针从用户空间逐个复制到内核空间 argv 数组
  memset(argv, 0, sizeof(argv));
  for(i=0; ; i++){
    if(i >= NELEM(argv)) // NELEM(argv) 也是 MAXARG
      goto bad;
    if(fetchint(uargv + sizeof(char*)*i, (int*)&uarg) < 0) // 从用户空间读取一个指针
      goto bad;
    if(uarg == 0){ // 参数列表以 NULL 指针结尾
      argv[i] = 0;
      break;
    }
    if(fetchstr(uarg, &argv[i]) < 0) // 从用户空间读取参数字符串
      goto bad;
  }

  return exec(path, argv); // 调用核心 exec 函数

bad:
  return -1;
}
```
`sys_exec()` 的主要工作是从用户空间安全地获取可执行文件的路径 `path` 和参数数组 `argv`，然后将这些信息传递给位于 `kernel/exec.c` 的 `exec()` 函数。

核心的 `exec(char *path, char **argv)` 函数（`kernel/exec.c`）执行以下关键步骤来转换当前进程：

#### a. 加载 ELF 二进制文件

xv6 使用标准的 ELF (Executable and Linkable Format) 作为其可执行文件的格式。`exec()` 首先需要解析这个文件，并将程序的代码和数据加载到内存中。

1.  **打开可执行文件**：
    使用 `namei(path)` 函数根据路径名 `path` 找到对应的 inode。如果文件不存在或不是一个常规文件，则返回错误。

2.  **读取并验证 ELF 头部**：
    *   从 inode 中读取 ELF 头部（`struct elfhdr`，定义在 `elf.h`）。这通常涉及到底层文件系统操作 `readi()`。
    *   检查 ELF 头部中的“魔数” (`elf->magic`) 是否等于 `ELF_MAGIC`。如果不是，说明这不是一个有效的 ELF 文件，`exec()` 会释放 inode 并返回错误。

3.  **创建新的页目录并设置内核空间映射**：
    *   调用 `setupkvm()` 创建一个新的页目录，并为这个页目录设置好内核空间的映射（所有进程共享相同的内核空间映射）。如果 `setupkvm()` 失败（例如，`kalloc()` 无法分配页目录所需的物理页），则释放 inode 并返回错误。
    *   `setupkvm()` 会分配一个物理页作为页目录，然后调用 `mappages()` 将内核地址空间（从 `KERNBASE` 到 `PHYSTOP` 或 `KERNBASE` + `EXTMEM`）映射到这个页目录中。

4.  **加载程序段 (Program Segments)**：
    ELF 文件包含多个程序段头（`struct proghdr`，定义在 `elf.h`），每个段头描述了文件中一段数据（如代码段、数据段）应该如何被加载到内存中。
    *   `exec()` 会遍历 ELF 文件中的所有程序段头。
    *   对于每个类型为 `ELF_PROG_LOAD` 的段（表示该段需要被加载到内存）：
        *   **分配虚拟内存 (`allocuvm()`)**: 调用 `allocuvm(pgdir, oldsz, newsz)` 为该段分配虚拟内存。`oldsz` 通常是上一个段加载后的内存大小，`newsz` 是当前段的虚拟地址（`ph->vaddr`）加上其在内存中的大小（`ph->memsz`）。如果 `ph->vaddr + ph->memsz` 小于 `oldsz`，则说明段地址设置有问题，返回错误。`allocuvm` 会分配物理页并建立页表映射，如果失败则进行清理并返回错误。
        *   **从文件加载段数据 (`loaduvm()`)**: 调用 `loaduvm(pgdir, (char*)ph->vaddr, ip, ph->off, ph->filesz)` 将段的内容从 ELF 文件加载到刚分配的内存中。
            *   `pgdir`: 新的页目录。
            *   `(char*)ph->vaddr`: 该段在进程虚拟地址空间中的起始地址。
            *   `ip`: 指向可执行文件的 inode。
            *   `ph->off`: 该段数据在文件中的偏移量。
            *   `ph->filesz`: 该段数据在文件中的大小。
            `loaduvm` 会负责将 `ph->filesz` 字节的数据从文件读入到 `ph->vaddr` 开始的虚拟地址处。它会逐页进行，对于每一页，它会找到对应的物理页，然后调用 `readi()` 从 inode 读取数据到该物理页。
            注意：`ph->memsz` (段在内存中的大小) 可能大于 `ph->filesz` (段在文件中的大小)。这种差异通常出现在 BSS 段，BSS 段在文件中不占空间，但在内存中需要分配空间并清零。`allocuvm` 已经分配了 `memsz` 大小的内存，而 `loaduvm` 只加载 `filesz` 大小的数据。对于 `memsz > filesz` 的部分（BSS 段），`allocuvm` 分配的物理页已经被 `kalloc` 清零了，所以 BSS 段的零初始化是自然完成的。

#### b. 设置用户栈 (Setting up the User Stack)

当程序的代码和数据段加载完毕后，`exec()` 需要为新程序设置用户栈。

1.  **分配栈内存**:
    *   栈通常位于用户地址空间的顶部。`exec()` 首先记录当前已分配到的最高虚拟地址（通过加载程序段得到）作为旧的 `sz`。
    *   然后，它调用 `allocuvm(pgdir, sz, sz + 2*PGSIZE)` 来为栈分配两页内存。第一页作为真正的栈空间，第二页作为“保护页”（guard page），防止栈溢出直接踩到其他数据。
        *   `PGSIZE` 是页大小 (xv6 中是 4096 字节)。
        *   `allocuvm` 会将这两页内存清零。
    *   更新 `sz` 为 `sz + 2*PGSIZE`。
    *   `sp` (栈指针) 被初始化为新分配的栈区域的顶部，即 `sz`。由于栈向下增长，所以这是栈的初始最高地址。

2.  **复制参数到栈上**:
    用户调用 `exec(path, argv)` 时传入的参数列表 `argv`（包含多个字符串指针）和这些指针指向的字符串本身，都需要从旧进程的地址空间（或内核从用户空间复制过来的地方）复制到新进程的用户栈上。
    *   `ustack` 数组用于临时存放要在新栈上构建的内容。
    *   `exec()` 会从 `argv` 数组的末尾开始（不包括最后的 NULL 终结符），逐个将参数字符串复制到新栈的顶部（通过 `sp -= len; copyout(pgdir, sp, argv[i], len);`)。`copyout` 负责将内核中的数据安全地复制到新进程用户空间的指定虚拟地址 `sp`。
    *   复制完每个字符串后，会将该字符串在新栈上的地址（即当前的 `sp` 值）存入 `ustack` 数组中。
    *   参数字符串复制完毕后，`ustack` 中就包含了所有参数字符串在新栈上的虚拟地址。

3.  **设置 `argc`, `argv` 和伪返回地址**:
    在 C 语言中，`main` 函数通常声明为 `int main(int argc, char *argv[])`。`exec()` 需要在栈上为新程序的 `main` 函数准备好这些参数。
    *   栈指针 `sp` 首先对齐到 4 字节（`sp &= ~3;`）。
    *   然后，将之前保存在 `ustack` 中的参数字符串指针（现在是新栈上的地址）逐个压入栈中（`sp -= sizeof(char*); *(char**)sp = ustack[i];`）。这是在构建 `argv` 数组本身。
    *   压入 `argv` 数组的 NULL 终结符（`sp -= sizeof(char*); *(char**)sp = 0;`）。
    *   压入 `argv` 数组的起始地址（即当前 `sp` 的值，它指向栈上 `argv[0]` 的位置）：`sp -= sizeof(char*); *(char**)sp = uargv_on_stack;` (这里 `uargv_on_stack` 是之前计算好的 `argv[0]` 在栈上的地址)。
    *   压入参数个数 `argc`：`sp -= sizeof(int); *(int*)sp = argc;`。
    *   **伪返回地址 (Fake Return PC)**：最后，压入一个 0 作为 `main` 函数的返回地址（`sp -= sizeof(int); *(int*)sp = 0;`）。由于 `main` 是程序的入口，它不应该返回。如果 `main` 真的返回了，这个 0 返回地址会导致进程访问非法内存并终止，这是一种合理的行为。

#### c. 完成新进程映像的设置

至此，新程序的代码、数据和栈都已准备就绪。

1.  **更新进程结构**:
    *   `proc->sz = sz;`：更新当前进程的内存大小为新程序的大小（包括代码、数据、BSS、堆（初始为空）、以及栈）。
    *   `proc->tf->eip = elf.entry;`：将进程陷阱帧中的指令指针 `%eip` 设置为 ELF 文件头部中指定的程序入口点 (`elf.entry`)。这是新程序开始执行的第一条指令的地址。
    *   `proc->tf->esp = sp;`：将进程陷阱帧中的栈指针 `%esp` 设置为新栈的当前栈顶地址 `sp`（它现在指向 `main` 的伪返回地址）。

2.  **切换到新页目录并释放旧页目录**:
    *   获取当前进程 `proc`。
    *   `oldpgdir = proc->pgdir;`：保存旧页目录的指针。
    *   `proc->pgdir = pgdir;`：将进程的页目录指针更新为新创建的页目录 `pgdir`。
    *   `switchuvm(proc);`：让 CPU 开始使用新的页目录。这个函数会加载 `pgdir` 到 CPU 的 `%cr3` 寄存器，并刷新 TLB，使得后续的内存访问都通过新的页表进行翻译。
    *   `freevm(oldpgdir);`：释放旧的页目录以及它所映射的所有用户空间物理页。这是关键的一步，旧进程的内存映像至此被完全丢弃。

### 3. `exec()` 的返回值

一个非常特别的地方是，如果 `exec()` 调用成功，它**永远不会返回到调用它的程序中**。因为调用 `exec()` 的那个程序（包括其代码和数据）已经被新程序完全替换了。新程序会从其 `main` 函数（或 ELF 文件指定的入口点）开始执行。

`exec()` 只有在出错时才会返回。例如：
*   指定的可执行文件不存在或无权限访问。
*   文件不是有效的 ELF 格式。
*   内存不足，无法为新程序分配页目录、页表或程序段。
*   参数列表过长或参数字符串复制出错。

在这些情况下，`exec()` 会返回 -1 给调用者，调用者的程序映像保持不变，可以继续执行并处理这个错误。

### 4. 与文件系统的交互

`exec()` 与文件系统的交互主要体现在以下几个方面：

*   **读取可执行文件**: `exec()` 需要通过文件系统提供的接口（如 `namei()` 找到 inode，`readi()` 读取 inode 内容）来访问和读取 ELF 可执行文件的头部和程序段数据。
*   **inode 的角色**: inode 提供了关于可执行文件的元数据（如类型、大小）和数据块位置信息。`exec()` 在加载程序段时，会使用 inode 中的信息来定位文件在磁盘上的数据。
*   **文件权限**: 虽然 xv6 的权限模型简单，但在更完整的系统中，`exec()` 会检查当前用户是否有执行该文件的权限。
*   **路径解析**: `namei()` 函数负责解析 `exec()` 传入的文件路径，将其转换为对应的 inode。

总结来说，`exec()` 是一个复杂但功能强大的系统调用。它通过加载 ELF 文件、构建新的地址空间（包括代码、数据、栈）、设置初始寄存器状态（特别是 `%eip` 和 `%esp`），将当前进程转变为一个全新的程序实例。这个过程是实现程序执行和 shell 功能的基础。
